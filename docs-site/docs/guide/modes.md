# 五种模式：Build / Plan / Auto / Target / God

输入框左侧的模式按钮点一下循环切换：BUILD → PLAN → AUTO → TARGET → GOD → BUILD。五种模式的区别是 AI 的**权限范围**与**终止方式**。

## BUILD（构建模式）

默认模式，功能完整。AI 可以写文件、改代码、执行构建命令，但每次需要授权的操作都会弹窗问你。

日常开发用这个。

## PLAN（计划模式）

进入这个模式后，AI 的写操作权限会被底层直接拦截禁用（工具层拦截，而非仅靠提示词约束）。AI 只能读取代码、检索文件并构思方案，无法修改任何文件或执行写操作命令。

适合这些场景：

- 你还不确定怎么改，想先让 AI 探索代码库、出个方案。
- 改动涉及多个文件或架构决策，想先看计划再决定。
- 你只想问问题、了解现有实现，完全不想它动手。

方案讨论清楚后切回 BUILD 再动手。

## AUTO（自动模式）

权限全放行。所有工具调用（写文件、执行命令、终端操作）自动批准，不弹任何授权窗。

::: danger 这个模式权限极大
只有灾难性删除（比如 `rm` 根目录或系统目录）仍会被拦截，其余一律放行。适合你已经清楚知道风险、希望 AI 全自动跑批量任务的场景。不熟悉的项目或者不确定 AI 会干什么的时候，别用这个。
:::

## TARGET（目标驱动模式）

权限与 AUTO 一致全放行，区别在于**有明确的终止条件**。进入 TARGET 后，你发送的**第一条消息会自动设为目标声明**（由当前对话模型优化表达后生效，发送不阻塞），AI 会围绕这个目标自主规划并执行，直到以下任一情况终止并自动切回 BUILD：

- **目标达成**：AI 调用 `completeGoal` 声明完成，你在弹窗确认后退出。
- **连续失败**：连续多次工具调用失败达到阈值（默认 5 次）。
- **步数超限**：单次目标执行的工具调用次数达到上限（默认 50 步）。
- **手动中断**：你随时点按钮切到其他模式，已产生的检查点保留供回滚。

进入 TARGET 后输入框会提示「本条消息将自动设为目标」，发送第一条消息即设定目标并开始执行；顶部状态条会实时显示目标与步数/失败计数。与 AUTO 一样保留灾难性删除防护；与 AUTO 不同的是，AI 也能通过 `switchMode` 工具带 `goal` 参数主动进入 TARGET，而 AUTO 只能你手动进入。

阈值（最大步数、连续失败次数）可在设置页「目标驱动模式」分组里调整，适配不同复杂度的任务。

## AI 自己也能请求切换

除了你手动点按钮，AI 在规划清楚后也可以主动请求切换模式，你在界面上一键批准即可。比如它在 PLAN 模式下做完方案，会申请切到 BUILD 开始实施；它也能带目标声明申请切到 TARGET。

有两个方向上的限制：**AUTO 模式只能你自己手动进入**，AI 无法通过工具切进 AUTO。但反过来，处于 AUTO 模式时 AI 可以主动切到 PLAN——这是 AI 退出 AUTO 的唯一路径。TARGET 则可以由 AI 带 `goal` 参数主动进入，达成目标后调 `completeGoal` 退出。GOD 需要你在界面上点按钮进入，AI 无法自行进入。

## GOD（神谕模式 / 乙方公司）

GOD 模式把「你 ↔ AI」的关系重构为**甲方 / 乙方**协作：

- **你（甲方 / 投资者）**：只负责提出目标、指明方向、给出预算额度，不为单次工具调用做授权决策。
- **AI（乙方 / CEO 总汇报员）**：作为「AI 公司」的操盘手，把需求拆解、派发给**部门子代理**去并行执行，必要时组**评审团**对改动做多视角把关，再把结果作为结构化汇报呈现给你。

进入 GOD 后，你发消息提需求，AI 会：

1. **拆解**：把你的一句话需求拆成多个可并行的子任务（命名部门），一次派发给子代理执行。可指定不同子代理（保守 / 革新两种执行风格）与模型、思考强度。
2. **评审**：对重要改动，AI 会派 3 名只读评审（严苛 / 务实 / 建设）分角度审查，再让评审长 `forehead` 汇总成一个裁决（通过 / 返工 / 换风格），并列出必须修复的问题。
3. **收口**：AI 收齐各部门与评审结论后，向你输出结构化汇报（谁做的、谁审的、结果如何、花了多少额度），而不是倾倒执行细节。

GOD 与 AUTO 一样权限全放行（只保留灾难性删除防护），治理与取舍由 CEO 替你决定；你只需要在方向判断或预算取舍时回应它的提问（多为选择题）。中途想退出，把模式切回 BUILD 即可。

> 适用场景：跨多文件的复杂改动、需要在「保守 / 现代化」两种实现间取舍、或想要一方「先实现、再多视角评审」的落地流程。
